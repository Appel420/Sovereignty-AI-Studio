# Architecture Decision Records

Architecture Decision Records document decisions that constrain or explain the architecture. They supplement the normative specification and do not override it.

## ADR workflow

1. Copy the next available ADR number.
2. Record the context, decision, consequences, and rejected alternatives.
3. Link the ADR from the documentation index and relevant specification sections.
4. Update `docs/CHANGELOG.md`.
5. Obtain review before treating the decision as accepted.

## Status values

Use one of:

- `Proposed`
- `Accepted`
- `Superseded`
- `Deprecated`
